# react

<Lead>`<Glorpie>` is a living face in a span: give it a name and a size. It renders on the server as a soft placeholder in the face's own colour, and paints on the client.</Lead>

```tsx
import { Glorpie } from 'glorpies/react';

<Glorpie name="ada@lovelace.dev" size={48} />
```

## sizing

`size` takes pixels or any CSS length. A face is painted at its displayed size times the device pixel ratio, so it stays sharp, and it's painted again if it grows. To fill a container, give it `"100%"` and size the container:

```tsx
<div style={{ width: 120, height: 120 }}>
  <Glorpie name={user.id} size="100%" shape="squircle" />
</div>
```

## a photo, with a face behind it

People who upload a photo get their photo; everyone else, and anyone whose photo is still loading or fails, gets their face. `<Avatar>` sets the size and shape for both.

```tsx
import { Avatar, AvatarFallback, AvatarImage } from 'glorpies/react';

<Avatar size={56}>
  <AvatarImage src={user.photoUrl} alt={user.name} />
  <AvatarFallback name={user.email} />
</Avatar>
```

<AvatarDemo />

`AvatarFallback` takes every `<Glorpie>` prop except `size` and `shape`.

## many faces on a page

A page of faces costs less than it looks:

- every face shares one animation loop, and only faces on screen move;
- a face paints only once it comes near the screen, so a long list doesn't paint all at once;
- `priority` lets the faces that matter, like the one in your header, paint first.

## server components and next.js

`glorpies/react` is a client module (it starts with `'use client'`), so it can be used straight from server components, with no wrapper and no config. During server rendering each face is a placeholder in its own background colour, so the layout doesn't shift when it paints.

## accessibility

Every face has `role="img"` and an accessible name from `label` (default `"Avatar"`); pass the person's name. Faces hold still for readers who prefer reduced motion, whatever `alive` says.
