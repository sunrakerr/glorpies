# faq

## is it really the same face everywhere?

Yes. A name hashes to the same seed everywhere, and the seed drives every decision with plain arithmetic, so a face is built the same in every browser, on every server, in every version. Tests pin the faces of known names, and a release that changed one would be a breaking release.

Two honest footnotes about pixels, as opposed to faces:

- Every browser and canvas library smooths edges and blends paint its own way, so the same face drawn in Chrome, in Safari and on a server differs in the soft edges of its strokes. The shapes, colours and features are the same; individual pixels aren't.
- Functions like `Math.sin` round their last digit differently on ARM and x64 processors, so two machines can disagree about a coordinate by under a millionth of a pixel.

So the promise is the same face everywhere, not the same bytes. Within one renderer the bytes are the same every time, and the tests pin them on each platform they run on.

## how many faces are there? can two names share one?

9,007,199,254,740,992, one for each 53-bit seed: over a million for every person alive. Two names can land on the same seed, but rarely: among a million users, the chance that any two share a face is about 1 in 18,000.

## can someone choose their own face?

A name always gets the same face, so to let people choose, offer them a few (try `randomName()` for candidates, or a few seeds) and store the one they pick. Pass a seed number as `name` and you get that face.

## how heavy is it?

There are no dependencies. The drop-in script for `<glorpie-face>` is one file, loaded once for the whole page. Faces paint only when they come near the screen, share one animation loop, and stop moving when they're off screen or the tab is hidden.

## which frameworks does it work with?

All of them. There are components for [React](/docs/react), [Vue](/docs/vue), [Svelte](/docs/svelte), [Solid](/docs/solid) and [Preact](/docs/preact); anything else that renders HTML, like [Angular](/docs/angular) or [Astro](/docs/astro), uses the [`<glorpie-face>` element](/docs/html). On a server, the image route runs in Next.js, SvelteKit, Nuxt, Astro, Express, Hono, Bun and Deno.

## does it work with server rendering?

Yes. Every component renders a placeholder in the face's own colour on the server, sized and cropped, and paints in the browser. For a face in HTML that never runs script, like an email, use an image from [your own route](/docs/server).
